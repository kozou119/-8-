# 2026年度・宝物運搬コンテスト用 Zumo 制御

UNO R4 Minimaを載せた授業用Zumoで、自分の1台を開発するプログラムです。競技概要と「ロボット実験1～4」を仕様資料として参照しています。資料内の課題・レポート提出指示を今回の作業には適用していません。

資料で判明した配線とセンサーを接続処理に反映しました。**Arduino向けビルドと実機走行は未検証です。** 初期値は `CompetitionConfig.h` の `measured=false` で、較正・センサー表示だけを行い、走行しません。実機で停止距離・捕捉距離・方位の向き・ゴールへの押し込み距離を調整してから走行を有効にしてください。

資料にはサーボや保持スイッチの配線はありません。そのため追加機器を必須にはせず、既存の超音波から捕捉を推定します。超音波の製品名は資料から確定できませんが、必要な信号方式と配線は記載されています。LSM303はPololuライブラリで対応バリアントを自動検出します。

ZumoShield 2.1.0は公式に `architectures=avr` と宣言されています。この版のモーター・ボタンは `BoardIO.h` からArduino標準APIを使い、AVRのタイマーやポートレジスターに依存しません。UNO R4用には8bit PWMを明示し、-400～400を0～255に換算します。ZumoMotors/Pushbuttonライブラリは不要です。

## 競技での動き

探索→接近→捕捉推定→自陣方位へ旋回→運搬→自陣色を確認→押し切り→後退・離脱を繰り返します。

- 自陣色はRED/BLUEを設定し、自陣への方位は起動時に実測します。図の北を磁北と決めつけません。
- 黒枠・相手ゴールで前進を中止し、短く後退して旋回します。開始位置の線は `enterMs` の間だけ内側に向かって通過します。
- 捕捉はアーム内の距離範囲で、別々の3測定・120ms以上の安定を確認します。キャッシュを何度読んでも確認回数は増えません。近距離の急変、対象なし、古いデータで解除します。
- **捕捉は推定です。** カップ以外の物体や他のロボットを完全に識別できず、旋回中にカップを落とす可能性も残ります。PCにも「capture estimate / LIKELY」と表示します。
- 自陣色を60ms継続確認して止まった後、実測した時間だけ押し、後退して解放します。搬入試行数は得点ではありません。ライン完全通過・コースアウト・審判の判定は別途確認が必要です。
- 平地の回収を基本とします。加速度から18度超の傾斜を検出すると後退し、戻れなければ停止します。山上3点を積極的に狙う制御、3次元方位補正、衝突相手の識別は未実装です。
- 3分経過、走行中のボタン押下、センサー異常で停止します。停止後のボタン再押下では再始動しません。

個人得点を重視して、まず平地での繰り返し搬入を狙う構成です。勝率の評価や優勝の保証はできていません。実戦では接触、照明、磁気外乱、ランダム配置への調整が必要です。

## 起動・較正・調整

1. 車輪を浮かせるなどして、モーター方向、PWMの大きさ、停止距離を実機で確認します。既定の `measured=false` ではモーターを駆動しません。
2. `RobotHardwareConfig.h` の `CAPTURE_MIN_MM` / `CAPTURE_MAX_MM` を、アーム内にカップを置いた超音波実測値に合わせます。初期値35～75mmは仮値です。2cm以内は資料でも測定できない領域とされ、センサー位置の調整が必要になる場合があります。
3. `CompetitionConfig.h` で自陣色、機体ID、速度、開始位置からの進入・押し込み・後退・旋回の各時間を調整します。旋回120などの初期値も未調整です。実験1の注意に従い、摩擦で回れない低速指令にも注意します。
4. 起動後はUSBシリアル115200の案内に従います。較正中はモーターを回しません。最初にボタンを押して離し、水平を保ったまま手で2周以上回して地磁気X/Yの最小最大を取得します。もう一度押すか20秒で終了します。50サンプル以上と各軸の広がりを確認します。
5. 次にカラーセンサーを黒→白→赤→青の順に置き、各面でボタンを押して離します。各20サンプルを平均します。混色・飽和・識別不能な較正は拒否します。
6. 自陣ゴールの方向へロボットを向け、ボタンを押して離します。この方向を円周平均して運搬先として記録します。較正後に指定開始位置・方向へ移します。
7. `measured=false` ではここで較正済みのセンサー値を送信し続け、走行は無効です。捕捉表示、床色、向きをPCで確認できます。実機を右旋回させたとき方位が増える規約です。逆なら `COMPASS_CLOCKWISE_SIGN` を-1に変更して再較正します。
8. 機構、方位、停止距離、カップを完全にゴール線の向こうへ押せる時間を検証して `measured=true` に変更します。これは実機調整を置き換えるスイッチではありません。再起動して同じ較正を行い、READYを確認後、開始位置で競技開始に合わせてボタンを押します。

地磁気較正は水平面用です。モーター通電時の磁気外乱と右旋回時の方位変化を必ず確認してください。LSM303の既定6.25/7.5Hzから、検出した型に応じて50/75Hzに設定し、レジスターを読み戻して確認します。加速度・地磁気の読み取りはエラーと20msのタイムアウトを確認します。

超音波は60ms以上の間隔で読み、待ち時間を12msに制限します。無応答は対象なし（-1）として扱いますが、Echo断線や極近距離と対象なしは区別できません。最も古い測定の時刻を引き継ぎ、150ms超のデータでは停止します。不明色では即座に停止し、300ms継続した場合、または押し切り・解放中の場合は停止をラッチします。

再スタートは審判の指示に従います。リセットすると試合時計もリセットされるため、途中再配置では残り時間に合わせた `matchMs` の設定、またはチームによる残り時間での停止が必要です。時計の不揮発保存はありません。延長時は審判の指示に合わせて `matchMs=60000` として準備します。

## ビルドとテスト

Arduino IDEでは「Arduino UNO R4 Boards」を導入し、ボードを **UNO R4 Minima** にします。ライブラリマネージャーから **Adafruit TCS34725**（依存も導入）と **LSM303 by Pololu** を導入します。CLIなら次に相当します。

```sh
arduino-cli core update-index
arduino-cli core install arduino:renesas_uno
arduino-cli lib install "Adafruit TCS34725" "LSM303"
```

このリポジトリはフォルダ名と主スケッチ名が一致しないため、チェックアウト外に最新ソースをコピーします。

```sh
mkdir -p /workspace/.arduino-setup/sketch/Integrate
cp /workspace/-8-/*.ino /workspace/-8-/*.h /workspace/.arduino-setup/sketch/Integrate/
/workspace/.arduino-setup/bin/arduino-cli \
  --config-file /workspace/.arduino-setup/arduino-cli.yaml \
  compile --fqbn arduino:renesas_uno:minima --jobs 2 \
  --build-path /workspace/.arduino-setup/build/minima \
  /workspace/.arduino-setup/sketch/Integrate
```

このクラウドではCLI 1.3.1を導入済みですが、`downloads.arduino.cc` が403で拒否され、core・ライブラリ導入と実機向けビルドが未完了です。保存済みの許可ドメイン追加を環境設定で反映してから再開してください。ネットワーク操作時は既存 `HTTPS_PROXY` を `ARDUINO_NETWORK_PROXY` に引き継ぎ、値をログに出しません。

ホストテストはG++とJava 11以上（`jdk.compiler` を含む）で実行します。

```sh
cd /workspace/-8-
./tests/run.sh
```

AddressSanitizer/UndefinedBehaviorSanitizer付きで、両陣色の搬入、黒枠、捕捉喪失、傾斜からの退避、タイムアウト、手動停止、時刻の桁あふれ、出力制限、無作為系列を確認します。別テストで捕捉推定の別測定確認・キャッシュ・外れ値・喪失、地磁気の補正と向き、Arduino APIの模擬出力、通信パーサーを確認します。これらはUNO R4でのビルド・実走行やカップ運搬成功を示すものではありません。

## PC可視化

Processing 4で `visualization/ContestDashboard/ContestDashboard.pde` を開き、Serialライブラリを使います。コンソールの `Serial.list()` を確認して `PORT_NAMES` の最初の要素にXBeeドングルのポート名を設定します。残りは空文字のままで1台に使えます。9600bpsで送受信し、USB較正ログの115200とは別です。資料のSerial/MICRO切替は元のUNO向け説明も含むため、R4ではD0/D1のSerial1への配線とシールドの経路を確認してください。

状態、理由、実測距離、方位、捕捉**推定**、速度指令、搬入試行数を表示します。1.5秒受信がなければOFFLINEとし、古い値を現在値と誤認させません。複数ポートの同一IDは競合表示します。未測定の絶対位置や未確認の得点は生成しません。GUIと実ドングルでの動作は未確認です。

```text
V1,id,elapsed_ms,state,reason,floor,range_mm,heading_deg,held,left,right,attempts,sensorsOK
```

最大5Hzの13列CSVです。資料・旧コードの `H` バイナリ形式とは互換性がないため、付属の可視化と組み合わせます。状態・理由番号は `CompetitionController.h`、色はUNKNOWN=0/WHITE=1/BLACK=2/RED=3/BLUE=4、理由SLOPE=8です。無効方位と対象なしの距離は-1です。`held=1` は捕捉推定、`sensorsOK` は読み取り成功で、鮮度・範囲の最終判定は状態と理由に反映されます。

実験3の通信負荷への注意に従い、送信バッファに空きがなければ表示用パケットを捨て、制御を送信待ちで止めません。9600bpsの帯域内でも実際のXBee設定・バッファ容量との適合は実機で確認してください。
